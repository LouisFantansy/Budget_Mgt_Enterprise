## 1. 项目概述

### 1.1 项目目标

企业级预算管理系统旨在为研发部门提供一套完整的预算编制、审批、执行和监控解决方案。系统通过数字化手段实现预算全生命周期管理，提升预算管理效率和透明度。

### 1.2 项目范围

**包含范围：**
- 预算编制与调整
- 采购申请与审批
- 多级审批工作流
- 预算执行监控
- 数据导入导出（三单匹配）
- 报表分析
- 审计日志
- 系统管理

**不包含范围：**
- 财务核算系统对接
- 外部供应商管理
- 合同管理
- 资产管理系统

### 1.3 使用场景

| 场景 | 描述 | 涉及角色 |
|-----|------|---------|
| 年度预算编制 | 各部门在年初编制年度预算计划 | 部门负责人、预算管理员 |
| 预算调整 | 因业务变化需要调整已审批预算 | 部门负责人、预算管理员 |
| 采购申请 | 员工根据已批准预算提交采购申请 | 采购员、部门员工 |
| 审批处理 | 各级审批人处理待审批事项 | 部门负责人、预算管理员、财务、总监 |
| 预算监控 | 实时监控预算使用情况和执行率 | 预算管理员、财务、管理层 |
| 数据分析 | 生成各类报表进行预算分析 | 管理层、财务 |

## 2. 用户角色定义

### 2.1 角色总览

系统定义6个核心角色，采用RBAC（基于角色的访问控制）模型。

| 角色编码 | 角色名称 | 角色描述 |
|---------|---------|---------|
| admin | 系统管理员 | 系统超级管理员，拥有所有权限 |
| budget_manager | 预算管理员 | 负责预算审核和全局预算管理 |
| dept_head | 部门负责人 | 负责本部门预算和采购审批 |
| finance | 财务人员 | 负责财务相关审批和报表查看 |
| purchaser | 采购员 | 负责提交采购申请 |
| viewer | 普通用户 | 仅查看权限，可查看本部门数据 |

### 2.2 角色详细定义

#### 2.2.1 系统管理员 (admin)

**职责：**
- 系统配置管理
- 用户管理（增删改查）
- 角色权限管理
- 部门架构管理
- 审计日志查看
- 全量数据访问

**权限清单：**
```
用户管理: create, read, update, delete
角色管理: create, read, update, delete
部门管理: create, read, update, delete
预算管理: create, read, update, delete, approve
采购管理: create, read, update, delete, approve
审批管理: read, approve, reject
报表分析: read, export
系统设置: read, update
审计日志: read, export
```

#### 2.2.2 预算管理员 (budget_manager)

**职责：**
- 审核各部门预算编制
- 监控全公司预算执行情况
- 预算调整审批
- 预算汇总分析

**权限清单：**
```
预算管理: read, approve (全部门)
采购管理: read, approve
报表分析: read, export
```

#### 2.2.3 部门负责人 (dept_head)

**职责：**
- 编制本部门年度预算
- 审批本部门采购申请
- 监控本部门预算执行
- 提交预算调整申请

**权限清单：**
```
预算管理: create, read, update (本部门), approve (本部门)
采购管理: create, read, approve (本部门)
报表分析: read (本部门)
```

#### 2.2.4 财务人员 (finance)

**职责：**
- 财务合规性审核
- 预算执行监控
- 财务报表生成
- 三单匹配核对

**权限清单：**
```
预算管理: read (全部门)
采购管理: read, approve
报表分析: read, export
导入导出: import, export
```

#### 2.2.5 采购员 (purchaser)

**职责：**
- 提交采购申请
- 跟踪采购审批进度
- 查看本部门预算可用额度

**权限清单：**
```
预算管理: read (本部门预算额度)
采购管理: create, read (本人提交)
```

#### 2.2.6 普通用户 (viewer)

**职责：**
- 查看本部门预算信息
- 查看本人相关审批流程

**权限清单：**
```
预算管理: read (本部门)
采购管理: read (本人相关)
```

## 3. 功能需求清单

### 3.1 认证授权模块

#### 3.1.1 用户登录
- **功能描述：** 用户通过用户名和密码登录系统
- **输入：** 用户名、密码
- **输出：** JWT Token、用户信息、权限列表
- **业务规则：**
  - 密码使用bcrypt加密存储
  - 登录失败5次锁定账户
  - Token有效期7天，刷新Token有效期30天

#### 3.1.2 用户登出
- **功能描述：** 用户退出登录
- **业务规则：** 客户端清除Token，服务端可加入Token黑名单

#### 3.1.3 密码管理
- **功能描述：** 用户修改密码、管理员重置密码
- **业务规则：**
  - 修改密码需验证旧密码
  - 新密码长度不少于8位
  - 管理员可直接重置用户密码

#### 3.1.4 RBAC权限控制
- **功能描述：** 基于角色的细粒度权限控制
- **技术实现：**
  - 用户-角色多对多关系
  - 角色-权限多对多关系
  - JWT Token中包含用户角色信息
  - API级别权限校验

### 3.2 预算管理模块

#### 3.2.1 预算创建
- **功能描述：** 创建新的预算单
- **输入字段：**
  | 字段 | 类型 | 必填 | 说明 |
  |-----|------|-----|------|
  | 预算名称 | String | 是 | 预算单名称 |
  | 所属部门 | String | 是 | 部门ID |
  | 预算类型 | Enum | 是 | OPEX/CAPEX |
  | 年度 | Number | 是 | 预算年度 |
  | 预算明细 | Array | 是 | 预算项目列表 |

- **预算明细字段：**
  | 字段 | 类型 | 必填 | 说明 |
  |-----|------|-----|------|
  | 项目名称 | String | 是 | 采购物品名称 |
  | 费用类别 | String | 是 | 费用分类 |
  | 规格型号 | String | 否 | 技术规格 |
  | 单价 | Decimal | 是 | 预估单价 |
  | 数量 | Number | 是 | 采购数量 |
  | 合计金额 | Decimal | 自动 | 单价×数量 |

#### 3.2.2 预算查询
- **功能描述：** 分页查询预算列表
- **筛选条件：**
  - 部门
  - 年度
  - 状态（草稿/待审批/已审批/已拒绝/已调整/已关闭）
  - 类型（OPEX/CAPEX）

#### 3.2.3 预算编辑
- **功能描述：** 编辑草稿状态的预算
- **业务规则：** 仅草稿状态可编辑

#### 3.2.4 预算删除
- **功能描述：** 删除预算单
- **业务规则：** 仅草稿状态可删除

#### 3.2.5 预算提交审批
- **功能描述：** 将预算提交进入审批流程
- **业务规则：**
  - 提交后状态变为"待审批"
  - 根据金额自动确定审批级别
  - 冻结预算编辑权限

#### 3.2.6 预算调整
- **功能描述：** 对已审批预算进行调整
- **业务规则：**
  - 调整后生成新版本
  - 原版本保留历史记录
  - 调整需重新走审批流程

#### 3.2.7 预算汇总
- **功能描述：** 多维度预算汇总统计
- **维度：**
  - 按部门汇总
  - 按类型汇总（OPEX/CAPEX）
  - 按年度汇总

#### 3.2.8 预算使用追踪
- **功能描述：** 追踪单个预算的使用情况
- **显示信息：**
  - 预算总额
  - 已使用金额
  - 冻结金额（审批中占用）
  - 可用余额
  - 使用率百分比

### 3.3 采购管理模块

#### 3.3.1 采购申请创建
- **功能描述：** 基于已批准预算创建采购申请
- **输入字段：**
  | 字段 | 类型 | 必填 | 说明 |
  |-----|------|-----|------|
  | 关联预算 | String | 是 | 预算单ID |
  | 预算明细 | String | 否 | 关联预算明细项 |
  | 申请物品 | Array | 是 | 采购物品列表 |
  | 总金额 | Decimal | 自动 | 自动计算 |
  | 用途说明 | String | 是 | 采购用途 |
  | 紧急程度 | Enum | 是 | 低/普通/高/紧急 |

#### 3.3.2 采购申请查询
- **筛选条件：** 预算、状态、申请日期范围

#### 3.3.3 采购申请编辑
- **业务规则：** 仅草稿/被拒绝状态可编辑

#### 3.3.4 采购申请删除
- **业务规则：** 仅草稿/被拒绝状态可删除

#### 3.3.5 采购申请提交审批
- **业务规则：**
  - 提交时检查预算可用余额
  - 提交后冻结相应预算额度
  - 进入审批流程

### 3.4 审批工作流模块

#### 3.4.1 审批流程引擎
- **功能描述：** 动态审批流程管理

## 4. 数据隔离需求

### 4.1 隔离原则

| 用户角色 | 数据可见范围 |
|---------|-------------|
| admin | 全公司所有数据 |
| budget_manager | 全公司所有数据（预算相关） |
| finance | 全公司所有数据（财务相关） |
| dept_head | 本部门及子部门数据 |
| purchaser | 本部门数据 + 本人提交的数据 |
| viewer | 本部门数据 |

### 4.2 实现机制

1. **JWT Token中包含部门ID**：用户登录时，将departmentId写入Token
2. **API级别数据过滤**：每个查询接口根据用户角色自动添加部门过滤条件
3. **服务层权限校验**：敏感操作校验用户是否有权限操作目标数据

### 4.3 数据隔离矩阵

| 功能模块 | admin | budget_manager | dept_head | purchaser | viewer |
|---------|-------|---------------|-----------|-----------|--------|
| 预算列表 | 全部 | 全部 | 本部门 | 本部门 | 本部门 |
| 预算详情 | 全部 | 全部 | 本部门 | 本部门 | 本部门 |
| 采购列表 | 全部 | 全部 | 本部门 | 本人/本部门 | 本部门 |
| 审批列表 | 全部 | 全部 | 本部门 | - | - |
| 报表数据 | 全部 | 全部 | 本部门 | 本部门 | 本部门 |
| 用户列表 | 全部 | - | - | - | - |
| 部门列表 | 全部 | 全部 | 全部 | 全部 | 全部 |

## 5. 审批规则

### 5.1 金额分级规则

| 金额范围 | 审批级别 | 审批链路 |
|---------|---------|---------|
| < 5万元 | 2级 | 部门负责人 → 预算管理员 |
| 5万 ~ 50万元 | 3级 | 部门负责人 → 预算管理员 → 总监 |
| ≥ 50万元 | 4级 | 部门负责人 → 预算管理员 → 总监 → 总经理 |

### 5.2 审批角色定义

| 审批角色 | 职责 | 系统角色映射 |
|---------|------|-------------|
| 部门负责人 | 审核部门内预算和采购的合理性 | dept_head |
| 预算管理员 | 审核预算合规性和额度可用性 | budget_manager |
| 总监 | 审核大额预算和采购 | director |
| 总经理 | 终审超大额预算和采购 | gm |

### 5.3 审批流程状态

```
草稿 → 提交 → 审批中 → [批准/拒绝/撤回]
              ↓
         已批准 → 执行中 → 已完成
              ↓
         已拒绝 → 可重新编辑提交
              ↓
         已撤回 → 可重新编辑提交
```

### 5.4 预算冻结规则

| 场景 | 冻结金额 | 冻结状态 |
|-----|---------|---------|
| 采购申请提交审批 | 申请金额 | 冻结 |
| 采购申请批准 | 申请金额 | 转为已使用 |
| 采购申请拒绝 | 申请金额 | 释放 |
| 采购申请撤回 | 申请金额 | 释放 |

## 6. 非功能需求

### 6.1 安全性需求

| 需求项 | 要求 |
|-------|------|
| 身份认证 | JWT Token认证，支持Token刷新 |
| 密码安全 | bcrypt加密，最小8位长度 |
| 访问控制 | RBAC细粒度权限控制 |
| 数据隔离 | 部门级数据隔离 |
| 传输安全 | HTTPS加密传输 |
| 审计追踪 | 全操作审计日志 |
| 登录安全 | 失败5次锁定账户 |

### 6.2 性能需求

| 指标 | 目标值 |
|-----|-------|
| 页面首屏加载时间 | < 2秒 |
| 页面切换响应时间 | < 0.5秒 |
| API响应时间（P95） | < 500ms |
| 并发用户数支持 | 500+ |
| 数据库查询优化 | 常用查询<100ms |

### 6.3 可用性需求

| 需求项 | 要求 |
|-------|------|
| 系统可用性 | 99.5% |
| 数据备份 | 每日自动备份 |
| 故障恢复 | RTO < 4小时 |
| 浏览器兼容 | Chrome/Firefox/Edge/Safari最新2个版本 |
| 响应式设计 | 支持桌面端和移动端访问 |

### 6.4 可维护性需求

| 需求项 | 要求 |
|-------|------|
